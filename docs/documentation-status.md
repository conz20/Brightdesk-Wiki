# Documentation status

This page explains how to read the confidence labels used in this wiki.

| Label | Meaning |
| --- | --- |
| **Verified** | The described behaviour was checked against the named implementation, test or running product. The page records what was checked and when. |
| **Source-confirmed** | The repository or approved specification states this, but the end-to-end user workflow has not yet been independently verified. |
| **Planned** | The topic or capability is intended for future work. It is not a promise that it is available now. |
| **Under test** | Implementation exists, but the required checks are incomplete or still running. |
| **Not available** | The current verified scope explicitly excludes the capability. |
| **Needs review** | The page may be out of date or the source has changed. |

## Rules

- Never turn a planned feature into a verified instruction.
- Never call interface design artwork a product screenshot.
- Never call a configured package a released, tested installer.
- Include the product version, operating system and date when a user workflow is verified.
- Re-check a page when its source implementation, test or product specification changes.
- If evidence is missing, say so plainly rather than guessing.

## Page freshness

A page should identify its source and last verification date. If the underlying implementation changes, the page is flagged for review until the instructions are checked again.
